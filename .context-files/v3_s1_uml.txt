' ==========================================
' DESIGN NOTES
' ==========================================

note right of GameController
  GAME FLOW (sequential decisions)

  1. startTurn() advances the turn and
     processes arrivals.
  2. Manager makes ONE choice at a time:
     validate then execute immediately.
  3. A rejected choice (non-null String)
     changes no state and consumes no
     staff task; the manager redecides.
  4. Waiter acts before the Chef.
  5. endTurn() runs the automatic steps
     via TurnProcessor.
  6. checkResult() after turn 18.
end note

note right of GameState
  Encapsulation: all fields private,
  collection getters return unmodifiable
  views, no public setters.
  Status changes only via lifecycle
  hooks on Customer and Order.

  Composition: GameState creates and
  owns exactly 2 Tables.

  getDefeatCauses() lists missed
  victory targets for the CLI.
end note

note bottom of WaiterChoice
  Polymorphism: each concrete choice is
  a value object carrying only the ids
  it needs, avoiding an ambiguous
  generic target id.
end note

note bottom of TurnProcessor
  Automatic end-of-turn steps in fixed
  order: eating, payment (max 1, oldest
  first), satisfaction loss, abandonment.

  Customer.leave() lifecycle hook marks
  abandoned customers LEFT.
end note
